# 家計簿の要件定義

第2弾。スケジュール管理で作った家族・メンバー・認可（RLS）の土台をそのまま使う。

## 1. 目的

**続くこと**を最優先にする。

家計簿が続かない理由はいつも同じで、入力が面倒になるからである。
集計の細かさや分析の賢さは、入力が続いた後にしか意味を持たない。

そのため本機能の設計は次の順で判断する。

1. 入力が速いか
2. 入力し忘れたときに気づけるか
3. 見て分かるか
4. 分析ができるか

4のために1を犠牲にしない。

## 2. 使い方の前提

| | 内容 |
| --- | --- |
| 入力する人 | 主に2人（家計の主担当と配偶者） |
| 入力の頻度 | **1日に0〜5件**。買い物のたび |
| 入力する場所 | **レジを出た直後のスマートフォン**が中心。まとめ入力はパソコン |
| 見る頻度 | 月に数回。「今月あとどれくらい使えるか」を知りたい |
| 件数の見込み | 年間 1,000〜2,000件 |

**1件の入力は10秒以内**を目標にする。スケジュールと同じ基準。

## 3. 先に決めたこと

ここを曖昧にしたまま作ると、後から直すのが高くつく。

### 3.1 財布は家族で1つ

**誰が払ったかは記録するが、個人間の精算はしない。**

夫婦で「立て替えた・返した」を管理する使い方は対象外とする。
精算を入れると、貸し借りの残高・清算履歴・未精算の一覧が必要になり、
「家計を把握する」という目的から遠ざかる。

「誰が使ったか」は費目と同じく**記録の属性**として持ち、集計で見られるようにする。

### 3.2 残高は追わない

**口座やカードの残高、未確定の引き落としは扱わない。**

支払方法（現金・◯◯カード・◯◯銀行）は**ラベルとして持つだけ**にする。
残高を追うと、口座間の振替・繰越・実際の残高との照合が必要になり、
家計簿ではなく会計ソフトになる。

### 3.3 金額は整数（円）で持つ

小数は使わない。浮動小数点で金額を扱わない。

### 3.4 秘密の支出は扱わない

**家族の全員が、すべての記録を見られる。**
個人だけに見える支出という考え方は持ち込まない。
必要なら家計簿に入れない、で足りる。

### 3.5 月の区切りは1日から末日

給料日を基準にした締めは、必要になってから考える。

## 4. 機能要件

### 4.1 記録

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B01 | 支出を記録できる。項目は 金額・費目・日付・支払方法・使った人・メモ | Must |
| FR-B02 | 収入を記録できる。費目は収入用のものから選ぶ | Must |
| FR-B03 | **入力画面を開いてから保存まで、金額と費目の2つだけで終わる** | Must |
| FR-B04 | 日付の既定は今日。支払方法と使った人の既定は**前回と同じ** | Must |
| FR-B05 | 記録を編集・削除できる。削除は論理削除とし30日は戻せる | Must |
| FR-B06 | 同じ内容をもう一度記録できる（複製） | Should |
| FR-B07 | 1件の記録を複数の費目に分けられる（レシートの内訳） | Could |

FR-B03 の補足: 費目は**よく使う順に並べたボタン**から選ぶ。
プルダウンを開かせない。使った人と支払方法は既定のままで保存できるようにする。

FR-B07 は後回しでよい。スーパーの1回の買い物を食費と日用品に割るのは
正確だが、続かなくなる典型でもある。まずは「食費」でまとめて入れる。

### 4.2 費目と支払方法

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B10 | 費目は家族ごとに編集できる。最初はよく使うものが入った状態で始まる | Must |
| FR-B11 | 費目には色を付けられる。集計の色と一致させる | Must |
| FR-B12 | 費目の並び順を変えられる。使う順に並べておける | Should |
| FR-B13 | 使わなくなった費目は隠せる。過去の記録は残る | Must |
| FR-B14 | 支払方法を家族ごとに編集できる（現金・カード・電子マネーなど） | Must |
| FR-B15 | 費目に階層（大分類・小分類）は**作らない** | — |

FR-B15: 階層は集計が細かくなる代わりに、入力のたびに2回選ぶことになる。
続けることを優先して作らない。

**最初から入っている費目（案）**

支出: 食費 / 日用品 / 外食 / 交通 / 光熱費 / 通信 / 住居 / 医療 / 教育 /
被服 / 交際 / 趣味 / 車 / 保険 / その他
収入: 給与 / 賞与 / その他

### 4.3 固定費

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B20 | 家賃・光熱費・サブスクのような繰り返しの支出を登録できる | Must |
| FR-B21 | 繰り返しの指定は**スケジュールと同じ仕組み**を使う（毎月◯日など） | Must |
| FR-B22 | **自動では記録に入れない。**「今月まだ入れていない固定費」として一覧に出し、1操作で記録にする | Must |
| FR-B23 | 金額が毎月変わるもの（光熱費）は、金額を空にして登録できる | Must |

FR-B22 が重要。**引き落とされたかどうかを確かめずに実績へ混ぜない。**
自動計上にすると、実際には解約していたサブスクが毎月積み上がる。
「予定されている支出」と「実際に使った額」は別物として扱う。

### 4.4 予算

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B30 | 費目ごとに月の予算を決められる | Must |
| FR-B31 | 予算に対する使用額と残りを見られる | Must |
| FR-B31b | **入力中、選んだ費目の「今月の残り」がその場に出る。**いま入れようとしている額を足した状態で示す | Must |
| FR-B32 | 予算を超えた費目がひと目で分かる | Must |
| FR-B33 | 予算は月ごとに変えられる。指定が無ければ前月と同じ | Should |
| FR-B34 | 費目を決めない「全体の予算」も置ける | Should |
| FR-B35 | 予算の繰り越し（余った分を翌月へ）は**作らない** | — |

FR-B31b が予算機能の主役。予算がいちばん効くのは**お金を使った直後**で、
月末に集計を開いて見るものではない。集計画面を開く習慣が無くても効くようにする。

FR-B35: 繰り越しを入れると「今月の予算」が毎月変わり、その額が正しいのか
確かめにくくなる。「今月あとどれくらい使えるか」を知るのが目的なので作らない。

**8割を超えたら色を変え、超過したらラベルも出す。**色だけで伝えない。
状態の色（注意・超過）は費目の色とは別に取っておき、使い回さない。

### 4.5 集計

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B40 | 月の合計（支出・収入・差引）を見られる | Must |
| FR-B41 | 費目ごとの内訳を、額と割合で見られる | Must |
| FR-B42 | 前月との比較を見られる | Should |
| FR-B43 | 使った人ごとの内訳を見られる | Should |
| FR-B44 | 月をまたいだ推移（12か月）を見られる | Should |
| FR-B45 | 記録を検索・絞り込みできる（費目・人・期間・金額・メモ） | Should |

### 4.6 レシート

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B50 | 記録にレシートの写真を1枚添付できる | Should |
| FR-B51 | 写真は家族だけが見られる（Supabase Storage + RLS） | Must |
| FR-B52 | 記録を削除したら写真も消える | Must |
| FR-B53 | 写真から金額を自動で読み取る（OCR）は**作らない** | — |

FR-B53: 日本のレシートの読み取り精度では、結局すべて確かめることになる。
確かめる手間と入力する手間が変わらない。

### 4.7 取り込み

| ID | 要件 | 優先度 |
| --- | --- | --- |
| FR-B60 | CSV で記録をまとめて取り込める。スケジュールと同じ「塊で入れて、塊で消す」 | Should |
| FR-B61 | 銀行・カード会社との自動連携は**作らない**（00-product-vision.md 5章） | — |

## 5. データモデル（案）

```
families ──┬── budget_categories   費目（支出・収入）
           ├── payment_methods     支払方法（ラベル）
           ├── transactions        記録の本体
           ├── budgets             費目ごとの月の予算
           └── recurring_expenses  固定費
```

| テーブル | 主な列 |
| --- | --- |
| `budget_categories` | `family_id` `name` `kind(expense/income)` `color` `sort_order` `is_active` |
| `payment_methods` | `family_id` `name` `kind(cash/card/bank/emoney)` `sort_order` `is_active` |
| `transactions` | `family_id` `occurred_on(date)` `amount(integer)` `kind` `category_id` `payment_method_id` `member_id(使った人)` `note` `receipt_path` `recurring_id` `created_by` `deleted_at` |
| `budgets` | `family_id` `month(YYYY-MM-01)` `category_id(null=全体)` `amount` |
| `recurring_expenses` | `family_id` `name` `amount(null可)` `category_id` `payment_method_id` `member_id` `rrule` `is_active` |

**`amount` は整数（円）。** 支出も収入も正の数で持ち、`kind` で向きを表す。
符号で表すと、集計のたびに向きを思い出すことになる。

**`rrule` はスケジュールと同じ文字列**（`src/lib/recurrence/` で展開する）。

## 6. 画面

機能の中の2段目のタブ（docs/06-app-shell.md）。

| 画面 | 内容 |
| --- | --- |
| **入力** | 金額 → 費目 → 保存。既定で埋まっている項目は触らなくてよい |
| 一覧 | 月の記録。日付ごとにまとめ、絞り込みと検索 |
| 集計 | 月の合計、費目ごとの内訳、予算との比較、推移 |
| 予算 | 費目ごとの月額と、固定費の登録 |

**スマートフォンでは「入力」を最初に出す。** レジを出た直後に開くのがこの機能の主な使い方で、
そのとき見たいのは集計ではない。

画面の作りは試作で確かめた: [prototypes/budget.html](prototypes/budget.html)

- 触るのは**金額と費目の2か所だけ**。日付・支払方法・使った人は
  点線の1行にまとめ、変えたいときだけ開く
- 費目は色の付いた丸ボタン（38px以上）。プルダウンは開かせない
- 保存ボタンは親指の届く下に置く
- 金額の欄は数字のキーボードが出るようにする（`inputmode="numeric"`）

## 7. 受け入れ基準

| ID | 基準 |
| --- | --- |
| AC-B01 | 支出1件の入力が、画面を開いてから10秒以内に終わる |
| AC-B02 | 金額と費目だけで保存できる |
| AC-B03 | 月の合計と費目ごとの内訳が、1画面で分かる |
| AC-B04 | 予算を超えた費目が、色でひと目で分かる |
| AC-B05 | 固定費が「まだ入れていない」ものとして出て、1操作で記録にできる |
| AC-B06 | 記録が他の家族から見え、別の家族からは見えない |
| AC-B07 | 画面幅375pxで入力が完結する |

## 8. 作る順番（案）

| | 内容 | 規模 |
| --- | --- | --- |
| 1 | 費目・支払方法・記録（入力と一覧） | 中 |
| 2 | 集計と予算 | 中 |
| 3 | 固定費 | 小 |
| 4 | レシートの写真 | 小 |
