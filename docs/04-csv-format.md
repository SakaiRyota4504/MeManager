# 取り込みCSVの形式

対象: [02-schedule-requirements.md](02-schedule-requirements.md) 4.7「外部データの取込」の詳細
最初の利用先: football-data.org から作るサッカーの試合日程

---

## 1. 位置づけ

MeManager が外部データを受け取る口は、**ファイルの取り込み1つ**である。
アプリが外部サービスを直接呼ぶことはしない。

外部サービスごとの差異（認証方式、レート制限、レスポンス構造、利用規約）を
本体に持ち込むと、データ源が増えるたびに本体の改修が必要になる。
代わりに次の役割分担にする。

```
┌──────────────────┐  ①取得   ┌──────────────────┐  ②CSVを出力  ┌──────────────┐
│ football-data.org │ ───────▶ │ CSV作成プログラム  │ ──────────▶ │  CSVファイル  │
└──────────────────┘          │  （別途作成）      │              └──────┬───────┘
                              └──────────────────┘                     │
                                                          ③人が取り込む  │
                                                                        ▼
                                                              ┌──────────────┐
                                                              │  MeManager    │
                                                              └──────────────┘
```

本書が定めるのは **②で出力するCSVの形式** である。
この形式さえ守れば、データ源が football-data.org 以外に変わっても本体は無改修で済む。

③を人が行うことには利点がある。取り込み前にプレビューで内容を確認でき、
おかしなファイルをそのまま反映してしまう事故が起きない。

取り込みの頻度は **月1回（休日）と年1回（サッカーの年間日程）** を想定している。
年13回程度の操作のために自動化の仕組みを作る必要はない。

操作は **「塊で入れて、塊で消す」** で統一する。
取り込み1回分が1つのバッチとして記録され、
間違えたり日程が変わったりしたときは、そのバッチごと削除して入れ直す（3章）。

## 2. MeManager 標準CSV形式

### 2.1 基本ルール

| 項目 | 仕様 |
| --- | --- |
| 文字コード | UTF-8（BOM の有無は問わない） |
| 改行 | LF / CRLF のどちらでも可 |
| ヘッダ行 | 必須。1行目に列名を書く |
| 列の順序 | 自由。列名で判別する |
| 未使用の列 | 書かなくてよい。余分な列があっても無視する |
| 引用符 | 値にカンマ・改行・引用符を含む場合は `"` で囲む（RFC 4180） |
| 空欄 | 未指定として扱う |

ヘッダ行に `title` または `タイトル` があれば標準形式と判定し、
列マッピングの画面を飛ばして直接プレビューに進む。

### 2.2 列の定義

| 列名 | 日本語の別名 | 必須 | 内容 |
| --- | --- | --- | --- |
| `external_key` | `外部キー` | | 外部データ側の識別子。重複の検出に使う（3章） |
| `title` | `タイトル` | ○ | 1〜200文字 |
| `all_day` | `終日` | | `true` / `false`。既定 `false` |
| `start` | `開始` | ○ | 2.3 の書式 |
| `end` | `終了` | | 省略時は 2.3 の既定 |
| `assignees` | `担当者` | | メンバーの表示名を `;`（半角セミコロン）区切り |
| `calendar` | `カレンダー` | | カレンダー名 |
| `status` | `状態` | | `confirmed` / `tentative` / `cancelled`。既定 `confirmed` |
| `location` | `場所` | | 0〜200文字 |
| `description` | `メモ` | | 0〜2000文字 |
| `color` | `色` | | `#RRGGBB` |

`status` は日本語でも書ける（`確定` / `仮` / `中止`）。

**担当者とカレンダーの扱い**

どちらも列を省略できる。省略した場合は、取り込み画面で一括指定した値が使われる。
列に書いた場合は、そちらが優先される。

担当者は予定ごとに1人以上必要なので（FR-E06）、
`assignees` 列が空で、かつ画面でも指定がない行は取り込めない。
`assignees` に書いた名前が家族のメンバーに見つからない場合は、その行を警告として示す。

### 2.3 日時の書式

推奨は ISO 8601。

| 書き方 | 解釈 |
| --- | --- |
| `2026-09-19T14:00:00Z` | UTC の 14:00（日本時間の 23:00） |
| `2026-09-19T23:00:00+09:00` | 日本時間の 23:00 |
| `2026-09-19 23:00` | タイムゾーン指定なし → `Asia/Tokyo` として解釈 |
| `2026-09-19` | 日付のみ。`all_day` が `true` のときに使う |

`end` を省略したときの既定:

- `all_day` が `true` → `start` と同じ日
- `all_day` が `false` → `start` の1時間後

サッカーの試合は90分＋ハーフタイムで概ね2時間、
延長がありうる試合は2時間半を見込むとよい。**`end` は明示して出力することを勧める。**

タイムゾーンを指定しない書き方は、CSV を人が手で書くときの利便のために残している。
プログラムで生成する場合は `Z` 付きか `+09:00` 付きで出力すること。

### 2.4 記入例

football-data.org から作る場合の例。

```csv
external_key,title,all_day,start,end,status,location,description
football-data:match:497181,アーセナル vs リヴァプール,false,2026-09-19T14:00:00Z,2026-09-19T16:00:00Z,confirmed,Emirates Stadium,プレミアリーグ 第5節
football-data:match:497198,トッテナム vs エヴァートン,false,2026-09-26T11:30:00Z,2026-09-26T13:30:00Z,cancelled,,プレミアリーグ 第6節（延期）
football-data:match:497205,マンチェスター・シティ vs チェルシー,true,2026-10-03,2026-10-03,tentative,,プレミアリーグ 第7節（時刻未定）
```

3行目は、日程だけ決まっていて時刻が未定の試合。
終日の「仮」の予定として登録し、時刻が確定したら同じ `external_key` で更新する（3章）。

手で書く場合の例。

```csv
タイトル,開始,終了,担当者,場所,状態
ピアノ教室,2026-09-15 16:00,2026-09-15 17:00,たろう,市民センター,確定
歯医者,2026-09-18 10:30,2026-09-18 11:30,母,さくら歯科,確定
運動会,2026-10-10,2026-10-10,父;母;たろう,小学校校庭,確定
```

`all_day` 列が無くても、`開始` が日付だけなら終日予定として扱う。

月1回取り込む休日のような、毎月同じ形のファイルの例。

```csv
タイトル,開始,終了,担当者,状態
休み,2026-10-03,2026-10-03,父,確定
休み,2026-10-04,2026-10-04,父,確定
午前のみ,2026-10-09,2026-10-09,父,確定
休み,2026-10-12,2026-10-14,父,確定
```

3行目のように期間がある場合は `終了` に最終日を書く（その日を含む）。
担当者やカレンダーが毎回同じなら、列を省いて
取り込み画面のプリセット（FR-I17）で指定するほうが手間が少ない。

## 3. 入れ直しかた

### 3.1 消して入れ直す

日程が変わったとき、内容を間違えたときの対処は1つだけ。

```
取り込み履歴を開く → そのバッチを削除 → 新しいファイルで取り込み直す
```

予定を1件ずつ直す必要はない。数百件でもこの2操作で済む。
削除は30日間元に戻せるので、消してから気が変わっても復旧できる。

**差分更新（同じファイルを入れ直すと既存の予定が自動で更新される）は作らない。**
「消して入れ直す」で足りるものを差分更新に置き換えると、
「どの予定が更新されて、どれが据え置かれたのか」を毎回気にすることになる。
覚える操作が増えるだけで、得られるものがない。

### 3.2 external_key の役割

`external_key` 列は **重複の検出** に使う。更新には使わない。
DB 側でも一意制約にはしていない。「重複だと分かったうえでそのまま入れる」
（FR-I21）を選べるようにしてあるため。

| 場面 | 動作 |
| --- | --- |
| 同じファイルを続けて2回取り込んだ | 2回目は全件が重複として検出され、既定でスキップされる |
| バッチを削除してから同じファイルを取り込んだ | 重複にはならず、全件が新規として入る |

2つ目が成り立つのは、削除済みの予定を重複の対象にしないため。
「消して入れ直す」が主な操作なので、ここが逆だと何もできなくなる。

値の付け方は、**そのデータ源の中で一意**であればよい。
football-data.org なら試合ID（`football-data:match:497181`）が適している。
`.ics` を取り込む場合は UID が自動で使われる。

`external_key` 列は省略してもよい。
その場合は（タイトル・開始日時・カレンダー）の一致で重複を判定する。
ただし列を書いておくほうが判定は確実で、
将来 差分更新が欲しくなったときにも、データを作り直さずに済む。

## 4. football-data.org から CSV を作る

CSV作成プログラム側の実装指針。MeManager 本体の仕様ではないが、
正しい CSV を出力するために必要な事項をまとめる。

### 4.1 API の概要

| 項目 | 内容 |
| --- | --- |
| ベースURL | `https://api.football-data.org/v4` |
| 認証 | `X-Auth-Token` ヘッダにトークン |
| 試合の取得 | `GET /v4/competitions/{code}/matches?dateFrom=&dateTo=` |
| レート制限 | 無料プランで 10リクエスト/分 |
| 無料プランの対象 | プレミアリーグ、ラ・リーガ、ブンデスリーガ、セリエA、リーグアン、エールディヴィジ、プリメイラ・リーガ、チャンピオンズリーグ、ブラジル全国選手権、チャンピオンシップ、ワールドカップ、欧州選手権 |

**J リーグおよび国内アマチュアの試合は無料プランに含まれない。**
子どもが実際にプレーする試合の日程は、この経路では取得できない。
それらはチームから配られたファイル、または手書きのCSVで登録する。

### 4.2 列への対応

| football-data.org | CSV の列 | 変換 |
| --- | --- | --- |
| `id` | `external_key` | `football-data:match:{id}` |
| `utcDate` | `start` | そのまま出力（`Z` 付き）。日本時間への変換はしない |
| — | `end` | `start` + 所要時間（通常2時間、延長ありなら2時間30分） |
| `status` | `status` | 4.3 の対応表 |
| `homeTeam.shortName` / `awayTeam.shortName` | `title` | `{home} vs {away}` |
| `competition.name` + `matchday` | `description` | 例: 「プレミアリーグ 第5節」 |
| `stage` / `group` | `description` | ノックアウト時は「決勝トーナメント 準々決勝」など |
| `venue` | `location` | 提供されないことがある。無ければ空欄 |
| `score` | — | **既定では出力しない**（4.5 参照） |

`shortName`（`Arsenal`）は `name`（`Arsenal FC`）より短く表示に向く。
日本語表示にしたい場合は、CSV作成プログラム側にチーム名の対応表を持つ。
MeManager 側はチーム名を解釈しないので、どちらでも動く。

### 4.3 状態の対応

| football-data.org の `status` | CSV の `status` | 備考 |
| --- | --- | --- |
| `SCHEDULED` | `tentative` または `confirmed` | 4.4 の判定による |
| `TIMED` | `confirmed` | 日時が確定した状態 |
| `IN_PLAY` / `PAUSED` | `confirmed` | |
| `FINISHED` | `confirmed` | |
| `AWARDED` | `confirmed` | |
| `POSTPONED` | `cancelled` | タイトル末尾に「（延期）」を付ける |
| `SUSPENDED` | `cancelled` | 「（中断）」 |
| `CANCELLED` | `cancelled` | 「（中止）」 |

### 4.4 キックオフ時刻が未確定の試合

**ここが最も間違えやすい。**

日程だけが決まっていてキックオフ時刻が未定の試合は、
`utcDate` に仮の時刻（多くは `00:00:00Z`）が入る。
これをそのまま時刻付きの予定として出力すると、
日本時間では **朝9時の予定** として表示され、誤った情報になる。

次のように判定する。

```
utcDate の時刻部分が 00:00:00Z、かつ status が SCHEDULED
  → all_day=true, start=日本時間での日付, status=tentative
それ以外
  → all_day=false, start=utcDate（Zのまま）, status=confirmed
```

キックオフ時刻が確定して予定を直したくなったら、
そのバッチを削除して、新しいCSVで取り込み直す（3章）。
シーズン中に何度もやることではないので、これで足りる。

なお `status` の運用は提供側の都合で変わることがある（`TIMED` を使わなくなった時期がある）。
状態名だけに依存せず、**時刻が入っているかどうかで判断する**ほうが壊れにくい。

### 4.5 時差とスコアの扱い

**時差**: 欧州の試合は日本時間で深夜から早朝になる。
21:00 UTC の試合は翌日の 06:00 JST であり、日付が変わる。
`utcDate` を `Z` 付きのまま出力すれば MeManager 側が正しく変換するので、
CSV作成プログラムで日本時間に直そうとしないこと。
二重に変換して9時間ずれる事故が起きやすい。

**スコア**: `score` を `description` や `title` に入れると、
録画で観る家族にとって結果が見えてしまう。既定では出力しない。
入れたい場合は、CSV作成プログラム側のオプションとする。

### 4.6 CSV作成プログラムの推奨動作

| 項目 | 推奨 |
| --- | --- |
| 取得範囲 | 今日から90日先まで |
| ファイルの分割 | コンペティションごとに1ファイル。担当者やカレンダーを分けやすい |
| レート制限 | 10リクエスト/分。コンペティションごとに間隔を空ける |
| 取得に失敗したとき | **CSVを出力しない**（空や欠けたファイルを作らない） |
| 出力先 | 取り込みやすい固定の場所。ファイル名に取得日と範囲を入れる |

「取得に失敗したらCSVを出力しない」が重要。
中身の欠けたファイルを取り込み、プレビューで「ファイルに無い予定」を中止にしてしまうと、
本来ある試合まで中止になる。

### 4.7 利用条件

- 無料プランの利用範囲を超えないこと（レート制限の遵守）
- 取得したデータを第三者に再配布しないこと。本アプリは家族内での利用に閉じている
- 表示にあたって出典の明示が求められる場合は、カレンダーの説明欄にその旨を記載する

## 5. 標準形式でないCSV

チームから配られた日程表のように、列名が標準形式と違うファイルも取り込める。
その場合は取り込み時に列マッピングの画面が出て、
どの列がタイトル・日付・場所かを指定する（FR-I02）。

こちらは文字コードが Shift_JIS のことが多いため、自動判定を行う（FR-I04）。
標準形式は UTF-8 固定だが、標準形式でないファイルはこの判定を通す。

一度指定した列マッピングは名前を付けて保存でき、
翌年の日程表を取り込むときに再利用できる（FR-I15）。

## 6. 動作確認の項目

実装後、次を確認する。

| # | 確認内容 | 期待する結果 |
| --- | --- | --- |
| 1 | 標準形式のCSVを取り込む | 列マッピングを聞かれず、そのままプレビューに進む |
| 2 | 同じファイルをもう一度取り込む | 全件が「変更なし」になり、予定が増えない |
| 3 | `status` を `cancelled` にした行を取り込む | 予定が中止になり、取り消し線で表示される |
| 4 | `status` を `tentative` にした終日行を取り込む | 「仮」の終日予定として登録される |
| 5 | 標準形式でない Shift_JIS の CSV を取り込む | 文字化けせず、列マッピングを指定して取り込める |
| 6 | `assignees` に存在しない名前を書いて取り込む | その行が警告として示され、取り込み対象から外れる |
| 7 | `Z` 付きの `2026-09-19T14:00:00Z` を取り込む | 日本時間の 9月19日 23:00 として表示される |
| 8 | 1シーズン分（数百件）を取り込む | 取り込みが完了し、月表示・リスト表示が重くならない |
| 9 | 取り込み後にバッチを削除する | その取り込みで入った予定だけが消え、他は残る |

| 10 | バッチを削除してから、同じファイルをもう一度取り込む | 重複と判定されず、全件が新規として入る |
| 11 | 削除したバッチを元に戻す | 消えた予定が復活する |
