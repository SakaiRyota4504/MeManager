# 実装ロードマップ

スケジュール管理を動く状態まで持っていくための進め方。
各ステップは「終わった時点で何かが動く」ように区切る。

## 方針

- **ウェブを先に完成させ、デスクトップは後から包む。**
  デスクトップを先に作ると、両方を同時にデバッグすることになり進まない。
- **画面より先にデータ構造を固める。**
  担当者必須・繰り返し・インポートはすべてデータ構造に依存する。
- **外部データの取込は後回しにしない。**
  手入力で数十件を登録する状況が続くと、そもそも使われなくなる。
- **取込は1本にする。**
  外部サービスごとに取込口を作らない。CSV と .ics を読める口を1つ作り、
  データ源の違いは「CSV を作る側」で吸収する。
- **取込の頻度は月1回＋年1回。** 自動化は作らない。
  そのぶん「毎月の繰り返し操作を短くする」ことに手をかける。
- **塊で入れて、塊で消す。** 取り込みと一括削除は対で作る。
  差分更新は作らない。入れ直したいときは消して入れ直す。

## ステップ

### Step 0: 土台づくり

- Next.js プロジェクトの作成、TypeScript / Lint / フォーマッタの設定
- Supabase プロジェクトの作成、ローカル開発環境（Supabase CLI）
- Vercel へのデプロイと、環境変数の設定
- リポジトリの CI（型チェックと Lint）

**完了の目安**: 空の画面が本番URLで表示され、Supabase に接続できる。

### Step 1: 認証と家族・メンバー

対応する要件: FR-A01〜A09

- Supabase Auth によるサインアップ・ログイン・ログアウト
- `families` / `members` テーブルとマイグレーション
- サインアップ時に家族と「家族共有」カレンダーを自動作成
- メンバーの追加（アカウントなしのメンバーを含む）、表示名と色の設定
- 招待リンクの発行と受諾
- **RLS ポリシーをこの段階で入れる**（後付けにすると全テーブルの見直しになる）

**完了の目安**: 2つのアカウントが同じ家族に属し、別の家族のデータが見えないことを確認できる。

### Step 2: 予定の基本機能

対応する要件: FR-E01〜E11、FR-M01〜M04、FR-V01〜V07、FR-V09

- `calendars` / `events` / `event_assignees` テーブル
- 予定の作成・編集・削除（担当者必須のバリデーションを含む）
- 月表示・リスト表示
- 予定の詳細表示
- 担当者の色分け表示

**完了の目安**: 予定を登録して月表示に出せる。担当者なしでは保存できない。

### Step 3: 絞り込み

対応する要件: FR-M05〜M11、FR-V10、NFR-P02

- メンバー・カレンダー単位の表示切替
- 「自分の予定のみ」の切替
- 絞り込み状態の保存（`user_preferences`）と URL への反映
- 絞り込み中であることの明示

**完了の目安**: 受け入れ基準 AC-06〜AC-08 を満たす。

### Step 4: 週表示と操作性

対応する要件: FR-V02、FR-V03、FR-E07、9.3 節

- 週表示・日表示
- カレンダー上のクリック／ドラッグによる作成
- キーボードショートカット
- スマートフォン幅のレイアウト調整

**完了の目安**: 予定の追加が10秒以内に終わる。画面幅375pxで操作できる。

### Step 5: 繰り返し予定

対応する要件: FR-R01〜R08

- `rrule` 列と `event_exceptions` テーブル
- 繰り返し設定の入力UI
- サーバ側での展開（`/api/events`）
- 「この予定のみ / これ以降 / すべて」の編集・削除

**完了の目安**: 受け入れ基準 AC-09 を満たす。

### Step 6: CSV 取込と一括削除

対応する要件: FR-I01、FR-I04、FR-I10〜I16、FR-I20〜I29、FR-I30〜I32、FR-I50〜I54、FR-E12
詳細仕様: [04-csv-format.md](04-csv-format.md)

1. `events` への状態（確定／仮／中止）と `external_key` の追加
   — `external_key` の一意制約は `deleted_at IS NULL` の部分インデックスにする
2. 標準CSV形式の解析とプレビュー（`/api/import/parse`）
3. 担当者・カレンダーの一括指定と、取り込みの実行（`/api/import/commit`）
4. `external_key` による重複検出
5. **取り込み履歴の画面と、バッチ単位の削除・復元**
6. 「仮」「中止」の表示（取り消し線、中止の表示切替）

**取り込みと一括削除は同じステップで作る。** 削除が無い状態で取り込みだけを
使い始めると、間違えた取り込みを1件ずつ消す羽目になる。

**完了の目安**: 受け入れ基準 AC-12〜AC-19 を満たす。
サッカー1シーズン分（数百件）を取り込み → 削除 → 取り込み直し まで通す。

この段階では手書きのCSVで確認すればよい。
football-data.org からのCSV生成は別プログラムの作業になる。

### Step 7: 取り込みの繰り返しを楽にする（月1回の取り込み）

対応する要件: FR-I15、FR-I17〜I19、FR-I02〜I03、FR-I05〜I08

1. 列マッピング画面と文字コードの自動判定
2. **取り込みプリセット**（列マッピング・担当者・カレンダー・重複時の動作をまとめて保存）
3. 取り込み画面の手順説明（年1回でも迷わないように）
4. `.ics` の取り込み

**完了の目安**: 受け入れ基準 AC-10〜AC-11、AC-20 を満たす。
毎月の休日ファイルを「プリセットを選ぶ → ファイルを渡す → プレビュー → 実行」の
3操作で取り込める。

### Step 8: デスクトップアプリ

対応する要件: 9.5 節、NFR-C01、NFR-O03

- Tauri のシェルを作り、デプロイ済みウェブアプリを表示する
- OS通知、トレイ常駐
- グローバルショートカットとクイック入力
- ファイルのドラッグ&ドロップから取り込み画面へ
- 自動更新とインストーラの配布

**完了の目安**: 受け入れ基準 AC-02、AC-23 を満たす。

### Step 9: 仕上げ

- 通知・リマインダー（FR-N01〜N04）
- 検索（FR-S01〜S02）
- 祝日表示（FR-V11）
- Realtime による自動反映（FR-V08）
- .ics エクスポート（FR-I40）

## この後

スケジュール管理が日常的に使える状態になってから、家計簿に着手する。
Step 1 で作った家族・メンバーと RLS の仕組みは、そのまま家計簿でも使う。

先に3機能を並行して作り始めると、どれも中途半端で使えないまま終わる。
1機能ずつ「使える状態」にすることを優先する。
